# Transcript Work Suggested Patches

## Summary

Generate reviewable transcript cleanup patches when `transcript_work` is initialized. Raw
transcript artifacts stay unchanged, and `transcript/work/segments.toml` is changed only by the
existing low-risk text normalization: trim `ja` and drop empty Japanese segments.

The suggested patch pipeline writes files under `transcript/work/suggested-patches/`. It never
applies them automatically.

## Key Changes

- Extend segment patch TOML with optional top-level `name`, `summary`, and `created_by`.
- Extend each patch operation with optional `reason` and `confidence`, where confidence is
  `high`, `medium`, or `low`; these fields are documentation only and do not affect apply behavior.
- Remove direct small-gap retiming from `normalizeTranscriptWorkSegments`.
- Add transcript work suggested patch generation after `transcript/work/segments.toml` is created.
- Split output by simple filenames:
  - `<pass>-chunk-<index>-<start>s-<end>s-<confidence>.toml`
  - `<pass>-chunk-<index>-<start>s-<end>s-<confidence>.md`

## Pipeline

- `01-punctuation-cleanup`
  - `high`: edit Japanese text to remove ordinary comma/period-style subtitle punctuation.
  - Inline cleanup only replaces comma/period-style punctuation; terminal cleanup also handles
    wider sentence-ending marks such as colon, semicolon, and ellipsis.
  - Emits `edit` operations for cleaned text and `delete` operations for punctuation-only noise.
  - Later passes are generated from the virtual result of this cleanup so merge text does not
    restore punctuation that 01 removes.
- `02-fragment-merge`
  - `high`: same-speaker short fragment merge.
  - `medium`: speaker-flicker merge for short, rapidly alternating diarization fragments.
  - Emits ordered `merge` operations with `reason` and `confidence`.
- `03-boundary-retime`
  - `high`: edit adjacent boundaries with gap in `[-0.12, 0.08)` to create an 80ms gap.
  - Skips invalid durations, large overlaps, segments touched by fragment merge, and edits that
    would make either side shorter than 0.5 seconds.
- `04-long-segment-candidates`
  - `low`: Markdown report only for long, overly dense, or high-reading-speed Japanese segments.

## Test Plan

- Old patches still parse and apply.
- Patch metadata and operation `reason` / `confidence` parse without changing apply behavior.
- Invalid confidence values fail parsing.
- Transcript work initialization trims text and drops empty Japanese segments without direct gap
  retiming.
- Punctuation cleanup patches ordinary Japanese subtitle punctuation and emits delete operations
  when cleanup leaves no Japanese text.
- Punctuation cleanup does not rewrite internal colon text such as `第1部：開演`.
- Suggested patches are generated by pass, confidence, and audio chunk filename.
- Fragment merge patches are generated from punctuation-cleaned virtual segments and do not reference
  segments deleted by punctuation cleanup.
- High confidence patch files dry-run/apply through existing segment patch logic.
- Long segment candidates are emitted as Markdown reports, not applyable patches.
